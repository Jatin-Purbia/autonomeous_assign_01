# Experiments

All numbers come from `backend/experiment_outputs/` (`default_<type>.json`, `_runs.csv`, `_summary.csv`) and the tables in `docs/results/<type>.md`, generated by `python -m app.experiments.make_tables`. Runs are deterministic: re-running the commands below regenerates everything.

## Setup

| Item | Value |
|---|---|
| Layout | 20 x 14 shelf-and-aisle warehouse, 1 task (pickup, delivery) per robot at random free cells |
| Agent counts N | 5, 20, 40 |
| Dynamic-obstacle density rho | 0, 0.10, 0.20 (blocked cells / traversable cells) |
| Blockages | 50 % on cells used by planned paths, 50 % random; duration 6-14 steps |
| Disruption types | `cell_blockage`, `robot_breakdown`, `emergency_task`, `mixed` (one breakdown + one emergency + blockages) |
| Repetitions | 5 seeds per (N, rho) |
| Strategies | A single-agent repair, B local negotiated repair (proposed) |
| Runs | 3 x 3 x 5 x 2 = 90 per disruption type, 360 in total |
| Pairing | both strategies see the identical scenario and disruption list for a seed |
| Statistics | mean over **successful** runs, success rate over all runs; `*_summary.csv` also has sample std |
| Collisions | 0 in all runs (the engine asserts vertex/edge collisions) |

Reproduce:

```bash
cd backend
for t in cell_blockage mixed robot_breakdown emergency_task; do
  python -m app.experiments.batch_runner --type $t --out experiment_outputs --name default_$t
  python -m app.experiments.make_tables experiment_outputs/default_$t.json > ../docs/results/$t.md
done
```

A larger sweep can be run with `--agents 5 10 20 30 40 --density 0 0.05 0.10 0.15 0.20 --reps 20`.

## Results (all four disruption types, 360 runs)

| | A single-agent | B local (proposed) |
|---|---|---|
| Success rate | 87.8 % | **96.7 %** |
| Modified agents per run | 9.4 | 11.5 |
| Flowtime | 546.5 | 609.3 |
| Repair time (ms) | 103 | 171 |
| Messages | 7.0 | 11.7 |

Averages over successful runs are not directly comparable: A fails mostly on the hard instances (large teams), so its averages cover easier cases. In the 158 paired runs where both succeeded, B and A modify practically the same number of robots (9.43 vs 9.40); the extra modified agents in B's averages come from the harder runs only B can solve.

Success rate by team size (all types): N=5 98 % / 98 %, N=20 100 % / 100 %, **N=40 92 % (B) vs 65 % (A)**. By density: rho=0 98 / 98, rho=0.10 95 (B) vs 90 (A), **rho=0.20 97 (B) vs 75 (A)**.

By disruption type (success A / B): cell blockage 88.9 / 100, robot breakdown 93.3 / 97.8, emergency 91.1 / 100, mixed 77.8 / 88.9.

Affected-set behaviour of B: on average 0.28 expansions per run, no expansion in 81 % of runs, largest affected set 2.8 robots on average (maximum 9), 0 collisions.

## Multi-task robots (3 tasks per robot)

`experiment_outputs/multitask_mixed.*`: mixed disruptions, N = 5, 20, 40, rho = 0, 0.10, 0.20, 5 seeds, both strategies (90 runs, about 170 s).

```bash
python -m app.experiments.batch_runner --type mixed --tasks 3 --out experiment_outputs --name multitask_mixed
```

Success rate A 71.1 % vs B 75.6 %; no collisions. Success drops for both compared with one task per robot because tasks queue up and plans are longer.

## What the trimmed experiments can and cannot show

* They show that negotiation makes repair much more reliable under congestion (N=40, rho=0.20) at a modest cost in repair time and messages.
* They are small (5 seeds per cell), so single cells are noisy; read the trends, not individual numbers.
* The earlier version compared against a global-replanning baseline over 6000 runs. That baseline was removed, so the claim "local repair modifies fewer robots than replanning everything" is no longer tested here. Against single-agent repair, B does not modify fewer robots in the paired runs; its advantage is that it succeeds where single-agent repair cannot.
