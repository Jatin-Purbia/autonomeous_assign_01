# Experiments

All numbers below come from the files in `backend/experiment_outputs/` (`default_<type>.json`, `_runs.csv`, `_summary.csv`) and the tables in `docs/results/<type>.md`, which are generated by `python -m app.experiments.make_tables`. Nothing was typed by hand; re-running the commands below regenerates them (runs are deterministic).

## Setup

| Item | Value |
|---|---|
| Layout | 20 x 14 shelf-and-aisle warehouse (`scenario_generator.warehouse_map`), 1 task (pickup, delivery) per robot at random free cells |
| Agent counts N | 5, 10, 20, 30, 40 |
| Dynamic-obstacle density rho | 0, 0.05, 0.10, 0.15, 0.20 = blocked cells / traversable cells (`round(rho * |V|)` blockages) |
| Blockages | 50 % on cells used by planned paths (guaranteed to matter), 50 % on uniformly random cells/times; duration 6-14 steps |
| Disruption types | `cell_blockage` (the rho blockages are the disruptions), `robot_breakdown` / `emergency_task` (one event, plus the rho blockages as background), `mixed` (one of each + blockages) |
| Repetitions | 20 seeds (0..19) per (N, rho) |
| Strategies | A single-agent, B local negotiated (proposed), C global replanning (baseline) |
| Runs | 5 x 5 x 20 x 3 = 1500 per disruption type, 6000 in total |
| Pairing | all strategies see the identical scenario and disruption list for a seed |
| Statistics | mean and sample standard deviation over **successful** runs; success rate over all runs |
| Machine | 12 logical CPUs, Python 3.12.4, runs in an 8-process pool. Repair times are wall-clock milliseconds and depend on the machine |
| Collisions | 0 in all 6000 runs (the engine asserts vertex/edge collisions and would record an error) |

Reproduce:

```bash
cd backend
for t in cell_blockage mixed robot_breakdown emergency_task; do
  python -m app.experiments.batch_runner --type $t --reps 20 --seed 0 --out experiment_outputs --name default_$t
  python -m app.experiments.make_tables experiment_outputs/default_$t.json > ../docs/results/$t.md
done
```

## Hypotheses

| # | Hypothesis | Verdict | Evidence |
|---|---|---|---|
| 1 | More robots -> more congestion, flowtime, repair cost, modified agents | **Supported** (with a trivial part) | Flowtime is a sum over robots, so it grows with N by construction. Non-trivial: repair time B at rho=0.10 grows 19 -> 59 -> 175 -> 290 -> 514 ms for N = 5..40, modified agents 4.5 -> 8.2 -> 14.6 -> 20.2 -> 25.6. The modified *ratio* falls with N (0.80 -> 0.38 at rho=0.05) because the number of blockages is fixed by rho, not by N |
| 2 | More obstacles -> more detours, repair time, failure rate | **Partly supported** | Flowtime and repair time rise monotonically with rho for all strategies. Failure rate rises for A (N=40: 100 % -> 80 -> 70 -> 65 -> 30 % success) but **not** for B (2 failures in 500 cell-blockage runs) or C (none) |
| 3 | Local negotiated repair modifies fewer agents than global replanning | **Supported** | 11.97 vs 13.98 modified agents, B <= C in 100 % of 498 pairs; gap at N=40, rho=0.05: 15.2 vs 25.9 |
| 4 | Global may occasionally give lower flowtime, but higher repair time and plan disruption | **Supported, but "occasionally" understates it** | C has lower flowtime in ~80-90 % of pairs (about 10 % lower on average) at 4x the repair time. A confound: global replanning also re-optimises waits that the original prioritized plans contained, so part of its advantage is not repair quality |
| 5 | Local repair is most beneficial at low/moderate density | **Supported for the modified-agent gap** | Gap C - B at N=40 shrinks with rho: 10.7 (0.05), 7.9 (0.10), 5.9 (0.15), 4.0 (0.20); at rho=0.20 with N=5..10 both modify essentially every robot |
| 6 | At high congestion the affected component expands to include many robots | **Not supported in this setup** | Affected-set expansions are rare (<= 1.3 per run, N=40, rho=0.20) and the largest |A_d| of any single repair is about 6 of 40 robots (`Largest |A_d|` table). Most modifications come from many separate blockages each hitting a different robot, not from one repair spreading. Message counts for B grow with N and rho (see `Messages` table) |

## Other observations

* **Local vs single-agent (A).** B modifies the same number of agents as A (10.37 vs 10.37 in 448 pairs) and has the same flowtime. The value of negotiation is *feasibility*: A fails whenever a conflict with an unchanged plan appears (52 failures in 500 cell-blockage runs, up to 70 % failures at N=40, rho=0.20), while B recovers nearly all of them at almost the same cost (a few ms more repair time).
* **Failures of B and C.** They are dominated by instances where a repair is impossible for prioritized replanning (`no feasible route ... / group unsolvable`) and, for breakdowns, a broken robot stopping on another robot's pickup/delivery cell or in a place that walls off a route. C fails on the same kind of instances (breakdown: 42 vs 45).
* **Breakdown and mixed runs** fail 5-15 % of the time even at rho=0 for all three strategies (see `robot_breakdown.md`); this is inherent in the generated instances, not evidence for one strategy.

## Caveats (threats to validity)

* One synthetic layout and grid size; random tasks (1 per robot); a single blockage-duration range; targeted fraction fixed at 0.5. Conclusions may change with other layouts, longer task lists or different weights (`w4`, `lambda`, `mu`).
* Timings are wall-clock in a process pool on one machine; use them as relative, not absolute, values.
* Robots leave the grid at their last delivery, which keeps repair problems easier than with parked robots.
* Means are over successful runs only; a strategy that fails on hard instances can therefore look better on flowtime. Use the paired tables and the success-rate table together.
